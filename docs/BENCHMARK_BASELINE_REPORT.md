# JMT 并行优化 - 初始版本性能测试报告

**测试日期**: 2026-02-05  
**测试版本**: JMT v0.12.0 (串行版本)  
**测试环境**: macOS  
**编译配置**: release profile, sample-size=10

---

## 执行摘要

本报告记录了 JMT（Jellyfish Merkle Tree）串行版本在各种场景下的性能基准数据，作为后续并行优化的对比基准。

### 关键发现

1. **性能随数据规模线性增长**：处理时间与数据量呈近似线性关系
2. **键分布影响较小**：随机、集中、稀疏分布的性能差异在 10% 以内
3. **值大小影响显著**：值越大，处理时间越长（哈希计算和存储开销）
4. **冷启动略慢**：首次运行比预热后慢约 16%

| 1,000 keys | 839.93 µs | 724.09 µs | 953.12 µs | ~80 µs | [50,69,75,72,60,70,66,63,58,63,66,59,55,52,63,59] |
| 10,000 keys | 7.8578 ms | 7.3117 ms | 8.2883 ms | ~0.35 ms | [647,627,593,647,630,648,619,648,617,603,623,629,621,602,621,625] |

**性能特征**:
- ✅ 键均匀分布在 16 个子树中

## 并行优化预期

### 理论加速比

基于 16 叉树结构和当前性能数据，预期加速比：

| 数据规模 | 当前时间 | 预期时间 | 预期加速比 |
|---------|---------|---------|-----------|
| 100 keys | 79.962 µs | 80-100 µs | 0.8-1.0x |
| 1,000 keys | 839.93 µs | 280-420 µs | 2.0-3.0x |
| 10,000 keys | 7.8578 ms | 1.3-2.6 ms | 3.0-6.0x |
| 100,000 keys | 119.52 ms | 15-40 ms | 3.0-8.0x |

### 影响因素

1. **数据规模**: 大数据量（>1,000 keys）加速比更高
2. **键分布**: 均匀分布加速比最高，集中/稀疏分布加速比降低
3. **值大小**: 大值时加速比更高（哈希计算并行化）
4. **并行开销**: 小数据量时线程开销可能超过收益

### 边界情况

| 场景 | 预期加速比 | 原因 |
|-----|-----------|------|
| 小数据量（<100 keys） | 0.8-1.0x | 线程开销 > 收益 |
| 集中分布（2个子树） | 1.2-1.5x | 并行度受限 |
| 稀疏分布（部分子树为空） | 1.5-2.5x | 并行度受限 |
| 均匀分布（16个子树） | 3.0-8.0x | 最大并行度 |

## 结论

### 当前性能特征

1. ✅ **性能稳定**: 在各种分布下性能差异 < 15%
2. ✅ **线性扩展**: 1,000 keys 时接近线性扩展
3. ⚠️ **扩展性下降**: 100,000 keys 时扩展性降至 15.21x
4. ⚠️ **冷启动开销**: 首次运行慢 16.4%

### 并行优化建议

1. **设置并行阈值**: 最小 100 keys，避免小数据量性能下降
2. **动态并行度**: 根据数据规模和分布调整线程数
3. **缓存优化**: 使用线程局部存储避免锁竞争
4. **渐进式实现**: 先实现 depth=1 并行，再考虑更深层次

### B. 测试数据生成

所有测试数据使用 `rand` 库随机生成，确保可重复性：

```rust
// 随机键
let keys: Vec<KeyHash> = (0..count)
    .map(|_| {
        let mut key = [0u8; 32];
        rng.fill(&mut key);
        KeyHash(key)
    })
    .collect();

// 随机值
let values: Vec<OwnedValue> = (0..count)
    .map(|_| (0..value_size).map(|_| rng.gen()).collect())
    .collect();
```

### C. 异常值处理

Criterion 使用以下规则识别异常值：
- 低异常值：低于 Q1 - 1.5 * IQR
- 高异常值：高于 Q3 + 1.5 * IQR
- 严重异常值：超过 3 * IQR

### D. 性能指标定义

- **平均时间**: 10 次采样的算术平均值
- **最小值/最大值**: 10 次采样的最小/最大值
- **标准差**: 10 次采样的标准差
- **吞吐量**: ops/ms = 数据量 / 平均时间
- **加速比**: 串行时间 / 并行时间
